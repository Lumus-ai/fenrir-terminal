  (`fenrir_funpay.py`): модуль переносит готовые черновики в очередь
  со статусом queued (текст, message_id/order_id, время создания).

  отказ по классу из файла черновика. CLI: `fenrir funpay queue`,
  `fenrir funpay enqueue <draft-id>`, `fenrir funpay check --enqueue`.
  Отправки в браузер в модуле НЕТ (проверено тестом по исходнику):
  записи queued отправляет браузерный вотч и помечает их sent.

- Выполнение простых заказов: заказ из inbox.json (статус paid)
  с текстом задания выполняется агентом терминала (провайдер по
  умолчанию — Lix) в `~/workspace/funpay-shop/orders/<order-id>/`.

  Результат — файлы на диске + запись сдачи (kind=delivery) в
  очередь; файлы к чату заказа прикладывает вотч. CLI:
  `fenrir funpay fulfill [--inbox PATH] [--order ID] [--dry-run]`.
- Каждая постановка в очередь и каждое выполнение — строка в
  WORK_LOG.md через fenrir_worklog + запись в logs/funpay-watch.log.
  outbox.json и данные покупателей в GitHub не пушатся.

## v1.4-автожурлог — 07.11.2026

- Авто-журлог (`fenrir_worklog.py`, stdlib only): каждая выполненная
  задача сама пишет строку в `WORK_LOG.md` терминала (новый файл;
  файл оркестры не трогается). Формат — пересмотренный v1.4 из спеки
  (PLAN-EXTENDED.md, «Формат автожурнала v1.4»):
  `Дата | Время | Исполнитель | Задача | Статус | Примечания |
  Комментарий (авто)`, например:
  `2026-11-07 | 15:53 | scheduler | TST-001 Тест runner на Klinch |
  ok | ok (custom.klinch/gpt-6-luna) | [авто]`.
- Сознательные отступления от спеки: статус — ok/failed (единый
  словарь статусов терминала), а не «Завершено»/«Ошибка» из примера;
  ротация статусов по таймеру (12 ч) не берётся — журлог append-only,
  статусы задач живут в tasks.yaml; исполнитель — компонент
  (scheduler/agent/guard/backup/digest), а не имя человека.
- Хелпер `worklog()` — один на всех: запись атомарна (append +
  fsync), файл создаётся с заголовком при первом запуске,
  ретроспективных записей нет. Дедуп: строка, уже присутствующая
  в файле, не пишется повторно (повторный прогон того же действия
  в ту же минуту даёт ту же строку). Поля чистятся в одну строку
  (`|` → `/`, переводы строк — в пробелы, обрезка). Ошибки записи
  глушатся — хелпер никогда не роняет вызывающий код. Путь —
  env FENRIR_WORKLOG (для тестов) или <папка модуля>/WORK_LOG.md.
- Точки встройки: scheduler (`run_once`, после выполнения задачи),
  agent (`run_task` — обёртка: `log_worklog=False` для вызовов из
  планировщика, иначе было бы две строки на одно выполнение),
  guard (`ram_guard_check` — только WARN/CRIT, OK и dry-run не
  логируются), backup (`cmd_backup` — успех и два пути провала,
  dry-run не логируется), digest (`main` после записи файла,
  --no-write не логируется).
- Проверки живьём 07.11.2026: `test_worklog.py` — 33 проверки
  (формат, очистка, создание+дедуп, устойчивость к ошибкам,
  заголовок задачи агента, обёртка run_task со стабом, run_once
  с подменённым _run_one, dry-run ничего не пишет) — все прошли.
  Остальные suites после встройки: scheduler 57, digest 23,
  backup 27, ram_guard_v2 36, detect_done 23 — все зелёные.
  Живые прогоны: scheduler TST-001 на Klinch (20 с, done) —
  одна строка в журлоге; `fen morning` — одна строка; повторный
  `fen morning` в ту же минуту — дубля нет; повторный прогон
  scheduler — задача уже done, пропуск, строк не добавилось;
  `fenrir watchdog` при RAM 443 МБ [WARN] — строка guard с чисткой
  (удалено 2, ~288 КБ); `fenrir backup --no-upload` — строка
  backup («без загрузки»). `fenrir status` — по-прежнему v1.3.1,

- НЕ пушится: сам WORK_LOG.md с живыми записями (растёт каждый

## v1.4-планировщик (ядро) — 07.11.2026

- Ядро планировщика (`fenrir_scheduler.py`, stdlib only): единый
  `tasks.yaml` (путь `~/workspace/fenrir-terminal/tasks.yaml`),
  CLI `fen task add/done/list/run/validate` и runner
  `fen scheduler --once` (один проход; цикл — внешний крон раз в
  10 мин, крон НЕ создавался — его ставит человек:
  `*/10 * * * * .../bin/fenrir scheduler --once`).
- Формат tasks.yaml — YAML-подмножество со строгим парсером
  (`parse_yaml_subset`) и дампером (`dump_tasks_yaml`): отображения,
  списки отображений, скаляры (кавычки/plain/int/bool/null),
  flow-списки `[a, b]`, комментарии. `|`, `>`, `&`, `*`, `{...}`,
  табы — ошибка с номером строки. Выбор обоснован в шапке модуля:
  YAML требует спека, а JSON с расширением .yaml вводил бы в
  заблуждение; зависимостей не добавлено (PyYAML нет в stdlib).
- Схема задачи: id/title/task/workdir/status обязательны;
  kind code|text, provider klinch|lix (по умолчанию klinch),
  schedule manual|cron 5 полей, due ISO, max_steps 1..100,
  priority P0..P3, created/last_run/last_result. Валидация строгая:
  неизвестные ключи, дубли id, workdir вне ~/workspace, плохой
  cron/due — ошибка. Пути из спеки (~/fenrir, /opt/fenrir) НЕ
  брались — реальный путь tasks.yaml в терминале.
- Runner: только задачи todo с наступившим временем (due или
  cron-окно 10 мин с защитой от повтора по last_run); cron-задачи
  после выполнения остаются todo (рекуррентные), разовые — done/
  failed. Запись tasks.yaml атомарная после каждой задачи; lock
  `logs/scheduler.lock` (битый старше 10 мин пересоздаётся);
  всё — в `logs/scheduler.log` с ротацией >1 МБ.
