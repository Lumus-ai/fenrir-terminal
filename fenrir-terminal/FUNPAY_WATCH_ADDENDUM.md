# Дополнение к задаче крона funpay-watch-messages (FunPay v2.2, шаг 2)

Этот файл — текст, который родитель добавляет в задачу крона
`funpay-watch-messages` (браузер, каждые 30 мин). Сам крон этот файл
не читает: текст вносит родитель в определение крона. Терминал
отправки в браузер НЕ делает — отправляет только вотч.

## 1. Снимок входящих (уже действует)

При каждой проверке пиши свежий снимок в
`~/workspace/funpay-shop/inbox.json` (атомарно: во временный файл,
затем переименование), формат:

```json
{"fetched_at": "2026-11-07T16:00:00+04:00", "source": "browser-watch",
 "unread": 0,
 "messages": [{"id": "m1", "buyer": "Nick", "text": "...",
               "time": "2026-11-07 16:00", "order_id": null,
               "kind": "message"}],
 "orders": [{"id": "o1", "buyer": "Nick", "lot": "…",
             "status": "paid", "time": "2026-11-07 16:00",
             "task": "текст задания из чата заказа"}]}
```

`kind`: `message` | `order` | `system`. В заказ обязательно
включай `task` — текст задания покупателя из чата заказа (если его
нет, поле можно опустить: тогда терминал пометит заказ needs_owner).
Непрочитанные сообщения — все, что появились с прошлой проверки.

## 2. Отправка очереди (outbox.json) — новое в шаге 2

После проверки входящих прочитай `~/workspace/funpay-shop/outbox.json`
(поле `entries` — список записей). Отправляй ТОЛЬКО записи со
статусом `queued`, строго в порядке их `created_at`:

- `kind: "reply"` — текст записи (`text`) как есть, без отсебятины,
  без изменения смысла и без добавления цен. Адресат: `message_id` —
  чат с покупателем, `order_id` — чат заказа.
- `kind: "delivery"` — текст записи + прикрепить к чату заказа
  (`order_id`) все файлы из поля `files` (лежат в
  `~/workspace/funpay-shop/orders/<order-id>/`). Текст не менять.
- После успешной отправки каждой записи сразу же пометь её в
  outbox.json: `"status": "sent"`, `"sent_at": "<текущее время,
  Самара, ISO>"`. Сохраняй файл атомарно (временный файл +
  переименование), чтобы не потерять очередь при обрыве.
- Если отправка не прошла (карточка подтверждения загрузки, капча,
  ошибка, нет доступа к чату) — запись остаётся `queued`, не
  удаляй её и не помечай sent; доложи о проблеме как раньше.
- Запрещено: отправлять что-либо кроме записей из outbox.json;
  отправлять записи со статусом `sent`; менять текст записей;
  отправлять записи классов `phishing` / `aggression` (их в очереди
  быть не должно — если такая встретилась, не отправляй и доложи).

## 3. Отчётность — как раньше

Доложди в чат только: о новых продажах, о сообщениях, где нужно
решение владельца (в т.ч. помеченных терминалом needs_owner — смотри
`logs/funpay-watch.log` и `WORK_LOG.md` терминала), о проблемах
(не залогинен, капча, блокировка, неудавшаяся отправка из очереди).
При отсутствии нового — тихое завершение без отчёта.
