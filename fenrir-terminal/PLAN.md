# Фенрир Терминал — план и функции

Составлен 06.11.2026. Основание: что уже проверено живьём (см. TERMINAL.md, CHANGELOG.md, README движка).

## Принципы (не менять без слова Shadow)

1. **Stdlib only.** Python из коробки, без Bun/TS, без pip install — терминал должен подниматься после пересоздания VM одной командой.
2. **Файл на диске — сразу.** Каждый ответ модели пишется атомарно (tmp + os.replace) в момент получения. Пустой ответ = провал, не успех. Кап 6144 токена не трогать: `max_tokens` по умолчанию 2000, длинные задачи режутся на чанки.
3. **Честные отчёты.** Никаких выдуманных улучшений и процентов. Вердикт + пара фактов, детали в файлы. `fenrir status` показывает реальное состояние, даже если всё мертво.
4. **Ключи — только суррогаты.** Значения ключей нигде не хранятся и не выводятся. Запросы — только на разрешённые хосты, редиректы запрещены. User-Agent всегда нормальный (Cloudflare 1010 блокирует дефолтный Python-urllib — проверено 06.11.2026).
5. **Lix первый до 09.11.2026.** Безлимит, 260 RPM / 2M TPM / 6 параллельных. Klinch/Anymodel — фолбэк. После 09.11 — пересмотр маршрутов по живым лимитам.
6. **Модель файлы не пишет — пишет агент.** Модель возвращает `tool_calls`, файл на диск пишет цикл инструментов. Проверено: klinch7/gpt-6-luna делает tool_calls, агент `fenrir_agent.py` реально записал файл.

## v1.2 — надёжность (сначала, 1 день)

Цель: терминал переживает перезапуск VM и не врёт про состояние.

1. **Watchdog-cron каждые 5 минут.** Сейчас serve поднят разовым запуском, крона нет. Поставить `*/5 * * * * .../watchdog.sh`, проверить: убить serve, убедиться что крон поднял его сам.
2. **User-Agent везде.** 403 у Lix в probe — тот же Cloudflare 1010: в `fenrir_orchestra.py` нет нормального UA. Проставить `fenrir-agent/1.0` во все запросы движка и агента, перепроверить probe.
3. **`fenrir doctor` — самопроверка.** Один проход: serve отвечает? probe свежий (файл health не старше часа)? RAM? диск? Lix до дедлайна? Вывод: OK/FAIL по пунктам, без воды.
4. **`fenrir limits` — лимиты по ключам.** Живой опрос Klinch (все ключи) + остаток Lix-дней: использовано/осталось до сброса, одной таблицей. Сейчас лимиты проверяются вручную скриптами.
5. **Учёт токенов.** Считать факт из `meta.json`/`summary.json`: сколько токенов ушло за день по каждому провайдеру, запись в `state/usage-<дата>.json`. Основа для решения «куда гнать задачи завтра».

## v1.3 — сильный агент (после 1.2)

Цель: Луна (klinch7) и Lix-модели сами делают законченную работу в файлах, а не текстом.

1. **Больше инструментов агента.** Сейчас только write/read/list. Добавить: `append_file` (дописывать чанками без переписывания всего файла — главный способ обойти кап 6144), `edit_file` (замена точного фрагмента), `search` (grep по рабочей папке), `run_tests` (запуск `python3 -m py_compile` / тестов внутри workdir, вывод — модели).
2. **Маршрутизация моделей агента.** Код с инструментами — Луна klinch7 (доказано делает tool_calls). Текст/батч — Lix qwen3.8-max / deepseek-v4.1-flash. Фолбэк-цепочка при 403/429, как в движке. Выбор модели — флагом `--model`, по умолчанию по типу задачи.
3. **Очередь задач агента.** `fenrir agent --file tasks.jsonl` — как batch движка, но с циклом инструментов: каждая задача — свой workdir, свой лог шагов, итог — файл + отчёт.
4. **Верификация по умолчанию.** После записи агент сам проверяет: файл существует, начинается/заканчивается как надо, код компилируется. Если нет — дописывает сам, а не отдаёт недоделку. (Частично уже есть: nudge на read_file.)
5. **`fenrir agent` как команда терминала.** Сейчас агент — отдельный скрипт с длинной строкой запуска. Обернуть в `fenrir agent --task "..." --workdir ...`.

## v1.4 — автономность (параллельно с 1.3, по мере нужды)

Цель: потоки Shadow идут сами, Фенрир только докладывает.

1. **Планировщик задач терминала.** Единый `tasks.yaml`: что, когда, на какой модели, куда результат. Замена разрозненным кронам (FunPay-слежка 30 мин, поднятие 4 ч, TikTok/TG — когда Shadow включит автопостинг обратно).
2. **Ежедневный дайджест.** Утром одна короткая сводка: лимиты, потраченные токены, что сделано ночью, что упало. Формат — вердикт + факты, как любит Shadow.
3. **Бэкап на Google Drive.** `fenrir backup` — архив терминала + оркестры + WORK_LOG на Диск, по расписанию раз в день. Сейчас бэкапы делаются вручную.
4. **Журнал работ — автоматически.** Каждая задача пишет в WORK_LOG.md сама (что сделано, чем, результат), а не по памяти в конце дня.

## v2.0 — переезд на VPS (когда Shadow возьмёт сервер)

Цель: терминал живёт 24/7, а не на кронах песочницы.

1. **systemd-юниты** вместо крона: serve, watchdog, планировщик — как сервисы с автоперезапуском.
2. **Тот же код, тот же терминал** — переезд = перенос папок + ключей-суррогатов, без переписывания.
3. **FunPay полностью автономно с сервера**: слежка, поднятие, ответы покупателям, выполнение заказов.
4. **TikTok/TG-постинг с сервера** (если Shadow включит обратно) — без карточек одобрения песочницы.
5. Перед переездом — замер железа VPS (`free`, ядра, диск) и решение, что остаётся в песочнице (тяжёлые сборки APK — только `--no-daemon`, heap 512 МБ, по одной за раз).

## v2.1 — мульти-модельный роутер и экономика (после VPS)

Цель: каждая задача идёт на самую дешёвую живую модель, а не на первую попавшуюся.

1. **Живой прайс и лимиты.** Опрос всех провайдеров: кто жив, сколько осталось до сброса, цена за токен. Хранить в `state/prices.json`, обновлять каждый час.
2. **Автовыбор модели под задачу.** Код с инструментами — Луна klinch7 (пока жива) или deepseek-v4.1-flash; текст — самый дешёвый живой Lix; длинные чанки — та, у кого больше остаток. Выбор — по таблице лимитов, а не по привычке.
3. **Дневной бюджет токенов.** Лимит на день по каждому провайдеру, при приближении — предупреждение Shadow и перевод задач на фолбэк. Основа — учёт из v1.2.
4. **Алерты при исчерпании.** Если ключ умер (403/429/502) — задача не падает, а уходит на следующий живой провайдер, а Shadow получает одну строку в дайджесте.

## v2.2 — FunPay-автопилот с сервера (после 2.1)

Цель: магазин ИИ-услуг живёт сам, без ручной слежки.

1. **Слежка за сообщениями и заказами** — как сейчас крон каждые 30 минут, но с сервера и без пауз.
2. **Поднятие лотов каждые 4 часа** — с сервера, с журналом поднятий.
3. **Ответы покупателям** — шаблоны + модель, только по правилам Shadow (консультаций нет, API-лоты на паузе).
4. **Выполнение заказов** — простые заказы (арт, озвучка, апскейл) через движок терминала, результат — покупателю, журнал сделок — в WORK_LOG.

## v2.3 — контент-конвейер (после 2.2, когда Shadow включит автопостинг обратно)

Цель: TikTok и Telegram идут сами с сервера, без карточек одобрения песочницы.

1. **Очередь тем** — дедуп против сегодняшних и вчерашних слотов, стоп-лист, свежая новость вытесняет закреп.
2. **Рендер и постинг с сервера** — TikTok через Studio, Telegram через бота, проверка видимости (Only me → Everyone).
3. **Отчёты по слотам** — вердикт + факты, детали в файлы, как любит Shadow.

## v3.0 — саморазвитие терминала (после 2.3)

Цель: терминал сам улучшает свой код, а не ждёт, пока Фенрир допишет.

1. **Песочница для самоизменений.** Предложенный патч сначала — в копию, тесты, живой прогон; в прод — только после зелёных тестов.
2. **Патчи на утверждение Shadow.** Терминал предлагает улучшение (что, зачем, как проверено), Shadow говорит «да» — патч ставится. Без слова Shadow ничего само не меняется.
3. **Журнал самоизменений.** Каждое самоизменение — в CHANGELOG с пометкой «терминал сам», честно и проверяемо.

## v3.1 — мульти-агентный консилиум внутри терминала (после 3.0)

Цель: сложные задачи делают несколько агентов параллельно, без мёртвого совета Оркестры.

1. **Роли.** Кодер, ревьюер, тестер — три параллельных агента, каждый со своей моделью и своим workdir.
2. **Синтез.** Результаты ролей сводит координатор в один файл + отчёт. Конфликты — в отчёт, а не под ковёр.
3. **Очередь и лимиты.** Параллельность — не больше 6 воркеров (тариф Lix), очередь без пауз, как в batch движка.

## v3.2 — пульт с телефона (после 3.1)

Цель: Shadow управляет терминалом, не открывая песочницу.

1. **Telegram-бот как пульт.** Команды: статус, лимиты, запустить задачу, остановить, дайджест. Ответы — короткие, вердикт + факты.
2. **Подтверждения.** Опасные действия (перезапуск, удаление, трата лимита) — только после «да» от Shadow в боте.
3. **Уведомления.** Упало — одна строка в бот. Готово — одна строка в бот. Без спама.

## Что НЕ делаем

- Совет Оркестры (group-чат) — мёртв, не воскрешаем. Консилиум = 6 прямых вызовов + синтез.
- Anymodel для кода через инструменты — не делает tool calls, только короткие тексты.
- Грозные обещания про «настоящее AI-видео» — в регионе Shadow недоступно, только покадровая анимация.
- Темы, закрытые словом «забей» (Mindustry, крипто-покупатель, демо Chimera без ключа) — не переоткрываем.
