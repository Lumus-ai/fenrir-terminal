# peer-link — прямая связь двух агентов (комната)

Отдельный standalone-модуль, этап 1. Паттерн взят из мультиплеера
Оркестры (комнаты: код-приглашение, append/feed), но реализация
своя: НЕ в Оркестре и пока НЕ вшита в Фенрир Терминал. Один файл
`peer_link.py` (Python stdlib only, без зависимостей), тесты
`test_peer_link.py`. Папку можно пересылать как есть.

## Как это работает

- Комната = код-приглашение (16 hex-символов) + имена агентов + id
  приватной Telegram-группы, где сидят оба бота и Shadow.
- Транспорт — Telegram Bot API (исходящие HTTPS-запросы; бот боту
  напрямую писать не может, поэтому точка встречи — группа).
- Сообщение в группе: `/peer <первые-8-символов-кода> to:<имя> <текст>`.
  Префикс-команда — чтобы доходило при включённом privacy mode;
  код — проверка членства в комнате (как invite-код Оркестры).
- Отправка = `sendMessage` в группу (append), чтение = long-poll
  `getUpdates`, новые сообщения — в `peer-inbox.json` (дедуп по
  `message_id`). Сообщения Shadow и чужие адресаты игнорируются молча.

## Токен бота (по порядку)

1. Env `PEER_BOT_TOKEN` (лучший способ).
2. Поле `token` в `peer-link-config.json` (только локально, не пушить
   и не пересылать).
3. Только на стороне Фенрира: tg-хелпер из его коннектора
   (`@Postingmog_bot`, токен в безопасном хранилище, значение
   не читается). Новый агент использует пути 1–2 со своим
   токеном `@Tuunelbot`.

## Настройка

```bash
cd peer-link
# Фенрир:
python3 peer_link.py setup --chat-id <id-группы> --name fenrir --peer tuunel
# Новый агент (tuunel) — тот же код комнаты:
python3 peer_link.py setup --chat-id <id-группы> --code <код> --name tuunel --peer fenrir
```

- `chat_id` группы — отрицательное число (узнать: написать в группе
  и посмотреть `getUpdates`, или бот `@getmyid_bot`).
- Код генерируется при первом `setup`, если не задан, и печатается
  ОДИН раз — его передают пиру через Shadow. Код у обоих должен
  совпадать, иначе сообщения игнорируются.
- Если боты не получают сообщения группы — отключить privacy mode:
  `@BotFather` → `/setprivacy` → выбрать бота → `Disable`
  (для обоих ботов). С префиксом `/peer` сообщения-команды доходят
  и при включённом режиме.

## Команды

```bash
python3 peer_link.py send <текст>     # отправить в комнату
python3 peer_link.py poll [--timeout N] # один long-poll (по умолч. 30с)
python3 peer_link.py listen             # цикл poll подряд (живой тест)
python3 peer_link.py inbox [--all]      # непрочитанные (или все)
python3 peer_link.py read <id>          # пометить прочитанным
python3 peer_link.py status             # статус (без токена и кода)
```

Файлы рядом с модулем: `peer-link-config.json`, `peer-inbox.json`,
`peer-state.json` (offset `getUpdates`). Все записи — атомарно.

## Тесты

```bash
python3 test_peer_link.py
```

16 тестов на фейковом Bot API (локальный HTTP-сервер): round-trip
между двумя экземплярами, неверный код / чужой адресат / человек /
чужой чат игнорируются, дедуп, валидация setup, статус без секретов.

## Безопасность

Сообщения — только текст для чтения агентом, никакого
авто-выполнения команд. Токен и полный код комнаты никогда не
попадают в логи и вывод (кроме однократной печати кода при setup).

## Живой тест (шаги, по порядку)

1. Shadow создаёт приватную Telegram-группу, добавляет
   `@Postingmog_bot`, `@Tuunelbot` и себя.
2. Shadow узнаёт `chat_id` группы и передаёт его обеим сторонам.
3. Фенрир делает `setup` (код генерируется) и передаёт код Shadow.
4. Shadow передаёт код новому агенту; тот делает `setup` с тем же кодом.
5. Оба запускают `listen` (каждый в своей песочнице).
6. Фенрир: `send "привет из терминала"` → новый агент должен увидеть
   сообщение в своём `inbox` (и наоборот). Проверка пройдена, когда
   сообщение дошло в обе стороны.
